Mol-JEPA Embedding Pipeline

Authors: James Bannon, Michael Tran, Matthew Boccalon

Contact: bhklab.jamesbannon@gmail.com

Description: Pipeline for Generating Mol-JEPA Embeddings from HDD Compounds

This pipeline produces embeddings based on the pre-trained Mol-JEPA architecture. The pipeline functions by downloading data from the Harmonized Drug Dataset (HDD v3), selecting a compound universe of compounds with at least some labeled data, and using the pre-trained Mol-JEPA Architecture to produce the embeddings based on the compound's SMILES string.

At present the embeddings are the <CLS> token generated by the Mol-JEPA model.

Concretely, for constructing the drug universe we only keep molecules which are either: - In the Tox21 dataset

Or

  • have non-missing entry for at least one of the following columns in the HDD file coldata.tsv: 
"ATC.Code",
"Mechanism.of.Action",
"FDA.Approved",
'BBB.Permeable',
"LTKB.DILI.Annotation"  ,
"DILIrank.DILI.Severity.Grade",
"DILIrank.DILI.Annotation",
"DILIst.DILI.Annotation",
"Livertox.Hepatotoxicity.Likelihood.Score",
"Livertox.Hepatotoxicity.Likelihood.Reason",
"DIRIL.Label.Gong",
"DIRIL.Label.Shi",
"DIRIL.Toxicity",
"DICT.Cardiotoxicity",
"DICT.Label.Section",
"LTKB.DILI.Severity.Grade",
"DICT.Concern",
"DICT.Keywords"`

The code here can be run locally and also as a Nextflow pipeline.

At present the embeddings are the <CLS> token generated by the Mol-JEPA model.

Running Locally

Pixi is required to run this project. If you haven't installed it yet, follow these instructions. Once you've done follow these steps:

  1. Clone this repository to your local machine
  2. Navigate to the project directory
  3. Set up the environment using Pixi:
pixi install

Next navigate to workflow/scripts and run the folowing commands in order:

  1. pixi run "python3 download.py"
  2. pixi run "python3 construct_drug_universe.py"
  3. pixi run "python3 generate_embeddings.py"

This will put the resulting embeddings in the data/results folder.

Running with Nextflow

  1. Install Pixi. The locked environment includes Nextflow and Java.
  2. From the repository root:

bash pixi install --locked pixi run --locked pipeline

Nextflow downloads colData.tsv and Tox21.tsv using config/downloads.yaml, builds the molecule universe, and generates embeddings. The first run also downloads the pretrained Mol-JEPA model. The default device in config/embeddings.yaml is CPU. 3. Find molecule_embeddings.csv, embedding_qc.html, and the Nextflow trace, report, and timeline in data/results/nextflow/. When the workflow builds the universe, it also writes data/results/nextflow/data/procdata/molecule_universe.txt. Keep data/work/ and .nextflow/ to resume a run:

bash pixi run --locked pipeline -- -resume

To reuse local HDD inputs, pass the directory that contains HDD/colData.tsv and HDD/Tox21.tsv:

pixi run --locked pipeline -- --raw_data data/rawdata --outdir data/results/nextflow

Compounds missing SMILES or a PubChem CID are skipped. Join the output back to the universe on HDD.Compound.ID to check coverage.

Add --molset path/to/molecule_universe.txt to reuse a list of HDD compound IDs (one per line). Use --downloads or --embeddings to pass an alternate YAML config. Run pixi run --locked pipeline -- --help to see the workflow options.

To regenerate the QC HTML without recomputing embeddings:

pixi run --locked qc

This reads the default Nextflow CSV and local data/rawdata/HDD/colData.tsv. If Nextflow downloaded into its work cache, pass that run's exact labels TSV:

pixi run --locked qc path/to/molecule_embeddings.csv path/to/HDD/colData.tsv path/to/output

For applet builds and container uploads, see Deploying on DNAnexus.
